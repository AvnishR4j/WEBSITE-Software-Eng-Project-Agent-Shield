# Self-hosted deployment plan

This replaces the Vercel/Supabase publishing backend. The public frontend can remain on GitHub Pages.

## Architecture

- GitHub Pages: public website
- EC2: Node API and PostgreSQL, managed with Docker Compose
- S3: private uploaded deliverables
- Nginx plus a TLS certificate: exposes the API at `https://api.<your-domain>`

## AWS setup

1. Create a private S3 bucket and block all public access.
2. Create an IAM user or EC2 role that can only read, write and delete objects in that bucket.
3. Create an EC2 Ubuntu instance, assign a security group allowing HTTP/HTTPS and restricted SSH, then install Docker and Nginx.
4. Copy `.env.example` to `.env.production` on the server, set a strong `POSTGRES_PASSWORD`, `JWT_SECRET`, and unique bootstrap password, then add the S3 credentials or attach the IAM role.
5. Run `docker compose up -d --build` on the server. Verify `curl http://127.0.0.1:8080/health` returns `{ "ok": true }`.
6. Configure Nginx to proxy `/` to `127.0.0.1:8080`, issue a TLS certificate, and set `FRONTEND_ORIGIN` to the exact GitHub Pages origin.

## Before switching the frontend

Test the API health check, publisher login, an upload, a signed download, and a second version of the same deliverable. Keep the Vercel deployment available until every test passes.

## Security notes

- Never commit `.env.production`, S3 credentials, or JWT secrets.
- Keep S3 private; downloads are generated by the API as five-minute signed links.
- Add each team member as a separate `publishers` row with a distinct bcrypt password hash; do not share the bootstrap password.
- Configure AWS billing alerts before creating resources.
